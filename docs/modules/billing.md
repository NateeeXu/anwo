# Billing module (商业化) — `billing`

Owner: billing module agent. Server `server/src/modules/billing/**`, web `web/src/features/billing/**`, i18n `web/src/i18n/billing.ts`,
schemas `shared/src/schemas/billing.ts`, migration `server/src/db/migrations/18_billing.sql`, seed `server/src/db/seed/billing.ts` (version 5),
spec `docs/modules/billing.spec.mjs`, screenshots `docs/screenshots/billing/`.

Everything runs on **mock Stripe in test mode** — every checkout surface carries the non-dismissible band 「测试模式 Test mode · 不会真实扣款」, page
titles get a 「· 测试模式」 suffix and receipts say test mode. Nothing is hard-coded to Northwestern: prices are `pricing_plans` rows, partners and
promo codes are campus/state scoped, revenue and the Kit are filtered by `campusId`.

## Known gaps

- Production money movement is out of scope: Secure Payment requires a licensed payment partner (Stripe Connect or similar) before `escrow.enabled` is turned on outside dev; in the mock, released funds stay as wallet balance labelled "payout pending". `BILLING_LIVE` / Stripe Checkout is designed behind `mockStripe.ts` but not implemented.
- `wallet_topup` orders (API.md §11.2) are not offered: credits are boost-only and non-cashable per billing-requirements §7.
- Pro+ seats (`subscription_seats`) and listings CSV import are not exposed in the UI yet (the table exists; the seat count is shown).
- Sponsored placements (review fix, migration `20b_sponsorships.sql`): `sponsorships` + `sponsorship_invoices`, admin API (`GET|POST /admin/sponsorships`, `PATCH /admin/sponsorships/:id`, `POST /admin/sponsorships/:id/invoices`, `POST /admin/sponsorship-invoices/:id/:status`), public `GET /sponsorships?campusId&surface` (max 3 per campus on `home_feed`, 1 per Kit category) + tracked `GET /sponsorships/:id/go`, events `sponsorship.impression|click`, paid invoices unioned into admin revenue (`byKind.sponsorship`), labelled 「赞助」 strip on the home feed. Still missing: an admin UI for bookings (API only), the Kit-category card and the sponsored map POI layer, and the Verified Building tables.
- Referral "post bonus" needs `*.publish` events from listings / market / buddy (see integration requests); the seed shows one.
- Dispute evidence uploads use purpose `other` with `isPrivate`.
- Moderation-driven boost cancellation (`our_error` full refund vs `policy_violation`) is available as `cancelBoost(…, 'moderation')` + admin order refund but no admin UI button wires it to reports yet.
