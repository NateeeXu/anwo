## Findings

**F1 — production CSP blocks the inline theme script (minor).** `server/src/app.ts` `securityHeaders` sends
`script-src 'self'` for SPA pages, but `web/index.html` (→ `web/dist/index.html`) has an inline `<script>` that sets
`data-theme` / `lang` before first paint. In production Chrome logs
`Executing inline script violates the following Content Security Policy directive 'script-src 'self''` on every page.
Impact: no breakage (`bootTheme()` in `main.tsx` sets the theme once the bundle runs), but dark-mode users get a light
flash on first paint and the console is not clean. Fix options: add the script's hash
(`'sha256-pDisEc7+oi/JsgyyPCDLJVNK8a5IQo3/yMiRKS3Ed3k='`, as reported by Chrome) to `script-src`, or move the script to a
static file under `web/public/` loaded with `<script src>`. Not covered by `npm run e2e`, which runs Vite dev (no CSP).

**F2 — production WebSocket rejects same-origin when `WEB_ORIGIN` is unset (config/docs).**
`server/src/realtime/hub.ts` `originAllowed` only accepts `config.webOrigins` in production; the default is the dev
origins (`:5173`). With the README's production command (`JWT_SECRET=… NODE_ENV=production PORT=4500 … npm start`),
`ws://localhost:4500/ws` answers 403, so realtime chat, unread badges and notifications fall back to polling / do not
update live. Setting `WEB_ORIGIN=http://localhost:4500` (the public origin) fixes it — verified. Fix options: add
`WEB_ORIGIN=<public origin>` to the README / INTEGRATION production command, and/or accept an Origin equal to the
request's own `Host` when Express serves the SPA.
